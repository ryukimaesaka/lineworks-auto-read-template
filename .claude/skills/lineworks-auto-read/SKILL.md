# LINE WORKS 自動既読 セットアップ＆運用

このリポジトリは「自分がメンションされたグループ／個人トークだけ未読で残し、それ以外の未読グループを
**毎時自動で既読化**する」仕組み（GitHub Actions上でヘッドレスにWeb版トークを操作するRPA）。
このスキルは、利用者本人が自分のLINE WORKSアカウント用にこれを**立ち上げ・運用する**のを伴走する。

## 最初に必ず伝える前提（安全上の重要事項）

作業を始める前に、利用者にこの3点を伝え、理解を得てから進めること。理由まで添えると納得しやすい。

1. **既読化は取り消せない**。一度既読にしたトークを未読には戻せない。だから初回は必ず
   後述の **DRY RUN（既読化せず対象だけ表示）** で「何が既読化されるか」を確認してから本番に進む。
2. **非公式なRPA**（LINE WORKS公式機能ではなく画面自動操作）。UI変更で止まる可能性・利用規約上の
   リスクがある点を理解の上で使う。
3. **自分自身のアカウントだけ**に作用する。他人のトークには一切触れない。

## あなた（アシスタント）が絶対にやらないこと

- **利用者のLINE WORKSのID・パスワード・2段階認証コードを、あなたが入力してはいけない。**
  ログインは必ず本人が、開いたブラウザで行う（下記STEP2）。
- **`LW_STATE`（＝本人のログインセッションそのもの）の値を、チャット・ファイル・ログ等に書き出さない。**
  これは実質的な認証情報。GitHubのSecret欄へ貼るのも、原則**本人の手**で行ってもらう。

---

## まず判断：新規セットアップ？ それとも運用の相談？

- 「導入したい／まだ動いていない」→ **セットアップ**（このまま下へ）。
- 「もう動いている。止めたい／再開したい／除外語を足したい／状況を見たい／再ログインしたい」
  → **運用**。`references/operations.md` を読んでそれに従う。

迷ったら、GitHubの Actions に「LINE WORKS auto-read」の実行履歴があるか尋ねる／確認する。
あれば運用、無ければセットアップ。

## セットアップの流れ（伴走）

全体像と各ステップのGitHub画面操作の詳細は、同じリポジトリ直下の **`SETUP-GUIDE.md`** に画面つきで
書いてある。あなたはそれを参照しつつ、以下の順で利用者を案内し、自動化できる所は代行する。
GitHubをまだ持っていない人には `GitHubアカウント作成ガイド.md` を案内する。

### STEP 0. このリポジトリが「自分用のコピー」か確認
テンプレートから「Use this template」で作った**自分のPrivateリポジトリ**を、手元に取得して開いている
状態が前提。まだなら `GitHubアカウント作成ガイド.md` の手順で自分用コピーを作ってもらう。

### STEP 1. 必要なものを入れる（あなたが代行可）
リポジトリのフォルダで、Node.js があるか確認し、無ければ https://nodejs.org のLTS導入を案内。
あってから、あなたが実行してよい：
```bash
npm install
npx playwright install chromium
```

### STEP 2. ログインセッションを作る（ログインは本人／実行はあなた可）
```bash
node login.js
```
- ブラウザが開く。**ここで利用者本人が自分のLINE WORKSにログインする（ID／パスワード／2段階認証）。**
  あなたは代わりに入力しない。「開いたブラウザでログインしてください」と促して待つ。
- トーク一覧が表示されると自動で `state_cookies.json` が保存され、**貼り付け用のbase64文字列**が
  ターミナルに表示される。
- この文字列が `LW_STATE`。**値をチャットに貼らない・ファイルに残さない。**
  利用者に「ターミナルに出た1行をコピーしてください（Macなら `base64 -i state_cookies.json | pbcopy`）」
  と伝える。

### STEP 3. Slackの通知先を用意（任意だが推奨）
セッション切れ時に気づけるよう、Slack Incoming Webhook を用意してもらう（チーム共通のものでも可）。
作り方は `SETUP-GUIDE.md` STEP3。URLを控えてもらう。無ければ後からでもよい。

### STEP 4. GitHub Secrets を登録（貼り付けは本人）
利用者のリポジトリの **Settings → Secrets and variables → Actions → New repository secret** で登録。
あなたは「どのページで・どの名前で登録するか」を正確に案内し、**値の貼り付けは本人に任せる**。

| 名前 | 値 | 必須 |
|---|---|---|
| `LW_STATE` | STEP2のbase64 | 必須 |
| `LW_ALERT_WEBHOOK` | STEP3のSlack Webhook URL | 推奨 |
| `GH_PAT` | セッション延命用トークン（任意） | 任意 |

`GH_PAT` の意味と作り方は `SETUP-GUIDE.md` / `README-GITHUB-ACTIONS.md` 参照。未設定でも動くが、
設定するとセッションが長持ちする。

### STEP 5. 守りを固める（EXCLUDE_KEYWORDS）
既読化から守りたい部屋を先に設定する。**メンションされた部屋と1:1個人トークは既定で自動的に残る**ので、
それ以外に「名前で必ず残したい部屋」があれば、`.github/workflows/auto-read.yml` の `EXCLUDE_KEYWORDS`
にカンマ区切りで追記する（部分一致・**大文字小文字を区別**）。
例：`EXCLUDE_KEYWORDS: '社長,経営'`

- 編集方法は環境に合わせる：このフォルダがgit連携済みなら、あなたがファイルを編集してコミット＆プッシュ。
  ZIPから作った等でgitが無ければ、GitHubのWeb画面での編集を案内する。
- **記号の文字種に注意**（全角×・半角x・✕ などは別物として扱われる）。実際の部屋名からコピーさせると確実。
- 他の調整項目（`SKIP_DIRECT_MESSAGES` など）は `SETUP-GUIDE.md` の「動作の調整」表を参照。

### STEP 6. 必ずDRY RUNで確認 → 本番
いきなり自動実行させない。まず「何が既読化されるか」を確認する。

1. GitHub → **Actions** タブ（初回は「ワークフローを有効化」を許可）。
2. 「LINE WORKS auto-read」→ **Run workflow** → **DRY RUN にチェック** → 実行。
3. 実行をクリックし `Run sweep` のログを開き、`DRY_RUN:` の行に並ぶ部屋名（＝既読化される予定）を
   利用者に見せて確認する。守りたい部屋が混じっていたら STEP5 に戻って `EXCLUDE_KEYWORDS` を足す。
4. 問題なければ、もう一度 **Run workflow**（今度は DRY RUN のチェックを**外す**）で本番実行。
   `完了: {"read":N,...}` が出て、LINE WORKالسで未読が減っていればOK。

### STEP 7. 以降は自動
毎時0分に自動実行される（GitHubの都合で数分〜遅延あり）。基本は放置でよい。
最後に運用の要点（`references/operations.md` の内容）を一言添えて引き渡す。

## 運用（止める／再開／除外追加／状況確認／再ログイン）

`references/operations.md` に手順を集約。利用者の要望に応じてそれを開いて従う。要点だけ先に：

- **止める/再開する**：GitHubの Actions → ワークフローの「…」→ Disable / Enable workflow（可逆）。
- **除外語を足す**：`auto-read.yml` の `EXCLUDE_KEYWORDS` を編集してコミット（反映は次回実行から）。
- **状況確認**：最新実行の `Run sweep` ログの `集計:` 行（既読化対象・残した件数が分かる）。
- **再ログイン（Slackに「セッションが切れました」が来たら）**：STEP2をやり直し、`LW_STATE` を更新。

## うまくいかないとき

`references/troubleshooting.md` に、よくあるエラー（`セッション未設定`・playwrightバージョン不一致・
不審ログインによる再認証要求など）と、RPAが依存している内部仕様を記載。原因切り分けに使う。
