# 運用手順（止める／再開／除外追加／状況確認／再ログイン）

すべて利用者本人のリポジトリ上での操作。ブラウザ操作ツールがあればあなたが代行し、無ければ
利用者にクリック手順を案内する。GitHubへのログインは本人のセッションで行う（代行ログイン不可）。

---

## 1. 既読化を止める／再開する（可逆）

「いったん止めたい」＝ワークフローを無効化するのが確実で、後からワンクリックで戻せる。

**止める**
1. リポジトリ → **Actions** タブ → 左の「LINE WORKS auto-read」。
2. 右上の「…（Show workflow options）」→ **Disable workflow**。
3. 「This workflow was disabled manually」と出れば停止。毎時実行も手動実行も止まる。

**再開する**
1. 同じページを開く → 黄色い帯の **Enable workflow** を押す。
2. 次の毎時0分から再び動く（すぐ動かしたい時は Run workflow で手動実行）。

`gh` CLIが使えるなら `gh workflow disable auto-read.yml` / `gh workflow enable auto-read.yml` でも可。

---

## 2. 既読化しない部屋を増やす（EXCLUDE_KEYWORDS）

`.github/workflows/auto-read.yml` の `EXCLUDE_KEYWORDS` に、部屋名の一部をカンマ区切りで足す。
**部分一致・大文字小文字を区別**する。例：
```yaml
EXCLUDE_KEYWORDS: '社長,経営,all_'
```

注意点（取りこぼしの元なので必ず伝える）：
- **記号の文字種**：全角「×」(U+00D7)・半角「x」・「✕」などは別の文字として扱われる。
  実際の部屋名からコピーして貼ると確実。
- **大文字小文字**：`all_` と `ALL_` は別物。実際の表記に合わせる。
- `事戦` のように短い語は、別の部屋（例「人事戦略」）まで巻き込むことがある。意図を確認する。

反映は**次回実行から**。編集方法：
- フォルダがgit連携済み → ファイルを編集してコミット＆プッシュ。
- git無し（ZIP運用）→ GitHubのWeb画面で `.github/workflows/auto-read.yml` を開き、鉛筆アイコンで編集→Commit。

心配なら、変更後に **Run workflow → DRY RUN** で、守れているか（その部屋が既読化対象に出ないか）を確認する。

---

## 3. 稼働状況を確認する

1. リポジトリ → **Actions** → 「LINE WORKS auto-read」。
2. 直近の実行が**緑（success）**なら正常。赤（failure）や、履歴が止まっているなら要確認。
3. 中身：実行をクリック → ジョブ `run` → ステップ **Run sweep** のログ。
   - `集計: 総=.. 既読化対象=.. 残す(メンション)=.. 残す(個人)=.. 残す(除外語)=..` … その回の分類結果。
   - `完了: {"read":N,...}` … 実際に既読化した件数。
4. 実行間隔が不規則なのは正常範囲：GitHubの無料cronはベストエフォートで遅延・スキップがある。
   また**リポジトリが60日間無操作だとスケジュールが自動停止**するので、たまに手動Runかコミットで回避。

> `残す(除外語)` の数は「その回に未読があった、除外語に一致した部屋数」。部屋名そのものは
> 本番ログには出ない。どの部屋が対象かまで知りたい場合は、一時的に sweep.js のログ出力を足して
> DRY RUN する（恒久運用には戻す）。

---

## 4. 再ログイン（セッションが切れたら）

Slackに「⚠️ セッションが切れました」と届く、または Run sweep ログが `need_login` / exit 20 の時。

1. 手元PCのリポジトリフォルダで再度ログインセッションを作る：
   ```bash
   node login.js
   ```
   → ブラウザで**本人がLINE WORKSにログイン**（ID／PW／2FA）。base64が表示される。
2. GitHub → Settings → Secrets and variables → Actions → `LW_STATE` → **Update secret** に、
   新しいbase64を**本人が貼り付ける**（値はチャット・ファイルに残さない）。
3. 次回実行から自動で復帰。すぐ確認したいなら Run workflow で手動実行。

`GH_PAT` を設定していれば毎回セッションが更新され、切れる頻度が下がる。

---

## 5. 無料枠・運用コストの注意

- Privateリポジトリは Actions 月2000分まで無料。毎時（1回1〜2分）なら概ね収まる。
- 超えそう／安定させたい場合は、稼働時間を絞る（cronを `0 8-22 * * *` 等）か、
  リポジトリをPublicにする（Actions無制限）。Publicでも秘密情報はSecretsにのみ置くこと。
